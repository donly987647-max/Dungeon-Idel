# v0.17 전체 아이템 아트와 응답 최적화

재료·장비·제작 완제품 232종에 각각 픽셀 그림을 연결했습니다. 박멸 화면 상단의 500회/1.5%/100조우 설명 블록을 삭제했습니다. 보스 해금·등장·챕터 개방 규칙은 변경하지 않았습니다.

## 화면과 서버

- 본사 알림 배지를 매번 삭제·생성하지 않고 변경된 숫자만 갱신합니다. 중복된 OfficeUI 렌더 리스너를 제거했습니다.
- 박멸 지역 카드의 진행도·화물·상태만 갱신해 누르는 중인 버튼과 키보드 포커스를 유지합니다.
- 방어 용사는 같은 웨이브에서 DOM을 유지하며 transform으로 이동합니다. 요소 조회·장면 크기 측정은 갱신/크기 변경 때만 수행합니다.
- 아이템/재고 조회는 배열별 Map을 재사용합니다. 원본 행 참조를 유지해 수량 변경을 즉시 반영하고 배열 교체/길이 변경 시 갱신합니다.
- 인증 검증 후 하나의 내부 `game_client_state` RPC에서 상태를 구성합니다. 기존 11/17개 조회와 별도 tick 왕복을 대체하며 게임 tick과 보상 로직은 유지합니다.
- 새 클라이언트의 작업 응답은 동적 상태만 반환합니다. 기존 클라이언트에는 전체 상태를 유지합니다. 전체 카탈로그는 로그인/명시적 전체 새로고침 때 받습니다.
- 작업 전에 시작한 poll의 늦은 성공/오류 응답이 최신 상태를 덮어쓰지 않습니다.
- 새 RPC는 service_role만 호출하며 요청의 player ID는 Edge Function이 검증한 사용자 ID입니다. anon/authenticated 직접 호출은 금지합니다.

## 측정

2026-09-11 KST, 동일 네트워크·전용 임시 계정·각 5회 요청 중앙값. 네트워크 및 서버 부하에 따라 달라질 수 있습니다.

| 요청 | 변경 전 | 변경 후 |
|---|---:|---:|
| 전체 상태 | 951ms | 561ms |
| 주기적 상태 갱신 | 687ms | 374ms |
| 후보 잠금 작업 | 1,105ms | 536ms |
| 후보 잠금 응답 크기 | 221,784B | 3,681B |

합성 UI에서 동일 상태 갱신 60회 시 본사 childList 변경 480→0, 방어 780→0. 경과시간은 로컬 CPU·이미지 인코딩 부하에 따라 변하므로 실제 프레임 속도 향상률로 환산하지 않았습니다.

## 검증과 적용

- 실제 SQL 테스트: 전투·전리품·제작·판매·전직·회복·방어·수동 운영 및 신규 snapshot 격리/권한.
- 브라우저: 360/390/768/1280 폭, 제작/판매/방어/전투, 그림 232종/10시트, 지연 응답 순서 및 누르는 버튼 보존.
- Edge Function Deno 타입 검사.
- 운영 DB에는 snapshot 함수/인덱스만 추가하며 계정 초기화는 실행하지 않습니다. 성능 검증용 임시 계정만 검증 후 삭제합니다.

아트 프롬프트와 좌표는 `assets/items-v017/manifest.json`, 제작/압축 방법은 같은 폴더의 `README.md`에 있습니다.
