# v0.14.2 원정 마무리 검증

## 변경 범위

전투 수치/드랍률/회복 확률을 추가로 변경하지 않았다. 원정 HP 누적, 재편, 전멸 동작의 불완전한 연결을 마무리했다.

- 복구된 app.js가 삭제된 상단 상태바 DOM을 갱신하면서 본부 렌더를 중단하던 참조 제거.
- 출정 성공 후 전투 화면 이동을 하나의 경로로 통일. 구형 지연 전환 타이머와 박멸 subtree observer 제거.
- 진행 중인 던전은 4칸 고정 파티 현황만 표시. 즉시 충원 대신 파티 재편 화면 제공.
- 재편은 game_restart_expedition RPC에서 하나의 트랜잭션으로 수행. 실패하면 기존 원정 유지. 원정/몬스터 소유권, 타 원정 출동, 최대4명, 중복/지난 요청, 동일 구성 검사.
- 재편 후 이미 획득한 전리품과 던전 승리 진행도 보존. 새 원정은 새 HP로 시작.
- 탐색 중에도 누적 HP를 그대로 표시. 이전 전투 스킬/회복 연출을 재생하지 않음.
- 전투 마지막 턴 회복이 승리 결과의 partyHp에 누락되던 서버 코드 수정.
- 전멸한 원정의 버튼은 파티 편성으로 연결.
- 복구본에 남아 있던 중복 목록 버튼 및 전직 Lv1 초기화 안내 제거.

## 검증 방법과 범위

실사용 계정 데이터는 사용하지 않았다. 서버 검사는 무작위 UUID의 가상 데이터로 실행하고 ROLLBACK했다. 브라우저는 실제 HTML/CSS/JS를 Chromium에서 실행하되 모든 Supabase 응답을 합성 데이터로 대체했다.

서버 테스트 8개 통과: 잘못된 파티 요청 시 기존 원정 유지, 다른 계정의 원정 접근 거부, 동일 파티 재요청 거부, 성공 시 회원/화물/진행도 보존, 중복 재편 거부, 승리 후 HP 유지와 사망자 XP0, 회복500회 HP상한/부활없음, 전멸 시 원정종료와 보스게이트 초기화.

브라우저 테스트: 본부6시설/대장간, 출정1요청 후 해당 전투 화면, 전투 중 편성 잠금, 4칸/빈칸 표시, 재편 실패/성공, 탐색 HP 유지, 쓰러진 개체와 이전스킬, 우물 회복 표시 및 다음행동 해제, 전멸 후 재출정.
360/390/430/768/1024px에서 문서/모달 가로 넘침과 전투 이름/HP텍스트 교차를 검사한다. 모든 가능한 상태/OS/브라우저를 검증했다는 뜻은 아니다.

## 시간 계산 정정

이전 attrition_sim_v0141.py는 한 전투 전체를 2초 행동 하나로 계산했다. 이제 조우 및 매 전투 턴이 각각 2초를 소비한다. 속도 레벨 성장과 반올림도 수정했다.

신규 B급 재능88 슬라임, 산골 마을 일반전만 3,000회, 실제30분=900행동 기준 결과:

| 지표 | 결과 |
|---|---:|
| 30분 생존율 | 89.2% |
| 6승 이전 전멸률 | 6.1% |
| 처치 중앙값 | 87 |

이 결과를 다중파티/보스/장비/전체챕터의 보장된 밸런스로 해석하지 않는다. 기존 게임 수치는 이번 검증을 이유로 변경하지 않았다.

## 자동화

`tests/expedition-runtime.mjs`, `.github/workflows/expedition-runtime.yml`에 재현 가능한 실행 검사를 유지한다. 임시 소스 복구 스크립트와 파일을 자동 수정하는 임시 workflow는 최종 트리에서 제거했다. 새로운 영구 QA는 읽기 권한이며 게임 소스를 수정하지 않는다.

보안: 재편 RPC는 의도적으로 인증된 사용자에게만 노출하는 SECURITY DEFINER API이며 내부 auth.uid() 소유권 검사를 수행한다. 익명/PUBLIC 실행은 거부한다. 기존 프로젝트의 기타 보안 경고 전체를 해결했다는 의미는 아니다.

배포 여부는 Vercel production이 실제 최신 app.js/index.html을 제공하는지 별도로 확인해야 하며, GitHub 테스트 성공만으로 운영 반영을 단정하지 않는다.
